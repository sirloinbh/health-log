# #25 날짜별 기록 화면 틀

- 이슈: [#25](https://github.com/sirloinbh/health-log/issues/25)
- 브랜치: `feat/25-daily-record`

## 목적

수면, 식단, 술·담배, 병원 기록이 모두 날짜 단위라서, 날짜를 골라 그날의 기록을 보는 공통 화면을 먼저 만든다. 이후 기능 이슈는 이 화면의 빈 구역을 채운다.

## 변경 — 2026-10-31

- **화면:** `/daily/YYYY-MM-DD` 하루 기록 화면과 메뉴 항목을 추가했다. `/daily`는 오늘 날짜로 이동한다. 이전·다음 날, 오늘, 날짜 선택으로 이동한다(`frontend/src/daily.tsx`, `frontend/src/app.tsx`).
- **날짜 계산:** `frontend/src/daily-date.ts`가 날짜 문자열을 UTC로 계산해 브라우저 시간대의 영향을 받지 않는다.
- **오늘:** 브라우저 시계를 쓰지 않고 `/api/health`가 돌려주는 서버의 `serviceDate()` 값을 쓴다. 서버에 연결할 수 없거나 서버가 오류로 응답하면(DB 장애 포함) 추측하지 않고 오류를 보여준다.
- **없는 날짜:** `2026-02-30` 같은 주소는 오류 안내와 오늘로 돌아가는 링크를 보여준다.
- **미래 날짜:** 막지 않는다. 다음 병원 예약 같은 기록이 뒤따르기 때문이다.
- **빈 구역:** 수면, 식단, 술·담배, 하루 체크, 병원·약 카드를 배치했다.
- **문서:** `docs/next-steps/README.md`를 등록된 이슈 기준으로 갱신했다.

### 브라우저 확인

헤드리스 Chrome을 CDP(브라우저 원격 제어)로 움직여 뷰포트를 390×844와 1440×900으로 정확히 맞췄다.

| 항목                                                    | 390×844 | 1440×900 |
| ------------------------------------------------------- | ------- | -------- |
| `/daily`가 서버의 오늘(`2026-10-31`)로 이동             | 통과    | 통과     |
| 다음 날(`02-28`→`03-01`), 이전 날, 날짜 선택, 오늘 링크 | 통과    | 통과     |
| `/daily/2026-02-30` 오류 안내                           | 통과    | 통과     |
| 가로 넘침                                               | 없음    | 없음     |
| 콘솔 오류                                               | 없음    | 없음     |

- 처음에는 DB 연결만 가짜로 넣은 API로 확인했고, 1차 리뷰 뒤 실제 로컬 DB에 연결한 API로 다시 확인했다.
- `--window-size=390,844`로 찍은 스크린샷은 Chrome 최소 창 너비 때문에 오른쪽이 잘려 보였다. 앱 문제가 아니라 측정 방식의 문제였고, 뷰포트를 정확히 맞춘 측정으로 확인했다.
- 실제 휴대폰과 다크 모드 화면은 확인하지 않았다.

## 1차 리뷰 보완 — 2026-10-31

독립 리뷰 지적 7건 중 6건을 이 PR에서 고쳤고, 1건은 #50으로 분리했다.

- **자정 후 오늘:** 앱을 열어 둔 채 날짜가 바뀌어도 어제를 오늘로 쓰던 문제를 고쳤다. `/api/health`를 1분마다, 그리고 탭으로 돌아올 때 다시 조회한다.
- **연결 테스트:** `today`를 주입하지 않은 `/api/health`가 Asia/Seoul 날짜를 돌려주는지 고정한 시계로 검사한다(`backend/test/health.test.ts`).
- **스크린 리더:** 날짜 표시에 `aria-live="polite"`를 붙였다.
- **날짜 타이핑:** 한 번 입력하는 동안 방문 기록이 하나만 쌓이게 했다.
- **오류 경로 테스트:** 서버 500 응답과 연결 실패를 나눠 검사한다.
- **브라우저 재확인:** 앞 절의 표를 실제 로컬 DB에 연결한 API로 다시 확인했고 결과는 같다. 이 화면의 "오늘"을 주는 `/api/health`가 `SELECT 1`을 실행하므로, 처음 기록한 "DB 쿼리를 쓰지 않는다"는 설명은 틀려서 지웠다.

실제 키 입력으로 재현해 찾은 문제도 함께 고쳤다. jsdom은 입력칸의 칸별 입력을 재현하지 못해 단위 테스트로는 잡히지 않는다.

| 문제                                        | 원인                                                     | 수정                             |
| ------------------------------------------- | -------------------------------------------------------- | -------------------------------- |
| `2026` 뒤에 `12`를 치면 `202612-03-15`가 됨 | `max`가 없으면 Chrome이 연도를 6자리까지 받음            | `max="9999-12-31"`               |
| `2026 12 25`를 치면 `2026-02-05`가 됨       | 값을 입력칸에 다시 쓰면 Chrome이 입력 중인 칸을 초기화함 | 초안을 포커스가 빠질 때까지 유지 |
| 같은 날짜가 되어도 방문 기록이 쌓임         | 같은 주소로도 이동함                                     | 현재 날짜와 같으면 이동하지 않음 |

Chrome에서 `20261225`를 실제 키로 입력하면 `/daily/2026-12-25`로 이동하고 방문 기록은 1개 늘어난다. 390×844와 1440×900 모두 같다.

## 제한·후속

- 입력칸에 포커스가 있는 채로 브라우저 뒤로 가기(Alt+←)를 누르면, 포커스가 빠질 때까지 입력칸에 이전 값이 남는다. 제목의 날짜와 주소는 맞게 바뀐다.
- 날짜 허용 범위(입력칸 하한 2000-01-01, 미래 날짜 허용)는 임시로 정한 값이다. 사용자 결정이 필요해 [#50](https://github.com/sirloinbh/health-log/issues/50)으로 분리했다.

- 의존성 설치(`npm ci --ignore-scripts`)는 패키지 설치 차단 규칙에 따라 사용자가 직접 실행했다.
- 설치 때 `npm audit`가 18건(moderate 17, high 1)을 보고했다. 이 변경과 무관하며 vite는 `sirloinbh/project-standards#352`에서 다룬다.
