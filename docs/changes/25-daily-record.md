# #25 날짜별 기록 화면 틀

- 이슈: [#25](https://github.com/sirloinbh/health-log/issues/25)
- 브랜치: `feat/25-daily-record`

## 목적

수면, 식단, 술·담배, 병원 기록이 모두 날짜 단위라서, 날짜를 골라 그날의 기록을 보는 공통 화면을 먼저 만든다. 이후 기능 이슈는 이 화면의 빈 구역을 채운다.

## 변경 — 2026-10-31

- **화면:** `/daily/YYYY-MM-DD` 하루 기록 화면과 메뉴 항목을 추가했다. `/daily`는 오늘 날짜로 이동한다. 이전·다음 날, 오늘, 날짜 선택으로 이동한다(`frontend/src/daily.tsx`, `frontend/src/app.tsx`).
- **날짜 계산:** `frontend/src/daily-date.ts`가 날짜 문자열을 UTC로 계산해 브라우저 시간대의 영향을 받지 않는다.
- **오늘:** 브라우저 시계를 쓰지 않고 `/api/health`가 돌려주는 서버의 `serviceDate()` 값을 쓴다. 서버에 연결할 수 없으면 추측하지 않고 오류를 보여준다.
- **없는 날짜:** `2026-02-30` 같은 주소는 오류 안내와 오늘로 돌아가는 링크를 보여준다.
- **미래 날짜:** 막지 않는다. 다음 병원 예약 같은 기록이 뒤따르기 때문이다.
- **빈 구역:** 수면, 식단, 술·담배, 하루 체크, 병원·약 카드를 배치했다.
- **문서:** `docs/next-steps/README.md`를 등록된 이슈 기준으로 갱신했다.

### 브라우저 확인

헤드리스 Chrome을 CDP(브라우저 원격 제어)로 움직여 뷰포트를 390×844와 1440×900으로 정확히 맞췄다.

| 항목                                                    | 390×844 | 1440×900 |
| ------------------------------------------------------- | ------- | -------- |
| `/daily`가 서버의 오늘(`2026-10-31`)로 이동             | 통과    | 통과     |
| 다음 날(`02-28`→`03-01`), 이전 날, 날짜 선택, 오늘 링크 | 통과    | 통과     |
| `/daily/2026-02-30` 오류 안내                           | 통과    | 통과     |
| 가로 넘침                                               | 없음    | 없음     |
| 콘솔 오류                                               | 없음    | 없음     |

- API는 실제 `createApp`과 `serviceDate()`를 쓰되 DB 연결만 가짜로 넣어 띄웠다. 이 화면은 DB 쿼리를 쓰지 않는다.
- `--window-size=390,844`로 찍은 스크린샷은 Chrome 최소 창 너비 때문에 오른쪽이 잘려 보였다. 앱 문제가 아니라 측정 방식의 문제였고, 뷰포트를 정확히 맞춘 측정으로 확인했다.
- 실제 휴대폰과 다크 모드 화면은 확인하지 않았다.
