# #29 음식 영양성분 저장소와 출처 규칙

- 이슈: [#29](https://github.com/sirloinbh/health-log/issues/29)
- 브랜치: `feat/29-food-db`

## 목적

프랜차이즈 메뉴, 레토르트 식품, 즐겨먹는 음식의 조사 결과를 출처와 함께 저장할 곳을 만든다. 출처와 확인 날짜가 없으면 수치가 정확한지 나중에 검증할 수 없다.

## 변경 — 2026-10-31

- **DB:** `database/migrations/002_foods.sql`. 영양성분은 1회 제공량 기준이고 모르는 값은 NULL이다. 음수와 0 이하 제공량은 DB도 거부한다. 이름과 브랜드 조합은 중복될 수 없다.
- **API:** `backend/src/foods.ts`. `GET /api/foods?q=`, `POST /api/foods`, `PUT /api/foods/:id`. 삭제는 이슈 범위 밖이다.
- **검증 규칙:** 공식·공공 자료는 출처 주소와 확인 날짜, 제품 표기는 확인 날짜가 필수다. 출처 주소는 http와 https만 받는다.
- **조사 데이터:** 새 도구 없이 마이그레이션의 `ON CONFLICT`로 넣는다. 재실행해도 중복되지 않고, 확인 날짜가 더 새로운 조사만 기존 값을 바꾼다.
- **화면:** `frontend/src/foods.tsx`. 음식 메뉴, 검색, 추가·수정. 0과 "값 없음"을 구분해 표시한다.
- **규칙 문서:** `docs/food-data.md`.
- **오류 처리:** `backend/src/app.ts`의 자체 오류 처리를 공통 `standard/http.ts`의 `notFound`, `errorHandler`로 바꿨다. 404 응답에 `HttpError`가 필요했다.
- **테스트 안전장치:** 이 PC의 `TEST_DATABASE_URL`이 다른 프로젝트의 `study_test`를 가리키는 것을 발견했다. 쓰기가 있는 통합 테스트는 DB 이름이 `health_test`일 때만 실행하고, 아니면 이유를 표시하며 건너뛴다.

## 검증

- 추가한 테스트: `backend/test/foods.test.ts`(입력 거부), `backend/test/foods.integration.test.ts`(실제 DB), `frontend/src/foods.test.tsx`(화면)
- 로컬 `npm run check`: 통과. 프론트엔드 89개 통과. 백엔드 16개 통과, 7개 건너뜀. 건너뛴 7개는 `foods.integration.test.ts`이며 로컬에 `health_test`가 없어서 실행하지 못했다.
- DB 통합 테스트: 아래 CI 결과로 확인한다.
- `npm run knip`, `npm run standards:check`: 통과

## 제한·후속

- 음식 삭제는 없다. 필요하면 식사 기록(#30)과의 관계를 정한 뒤 별도 이슈로 다룬다.
- 검색 결과는 100개까지 표시한다. 조사 데이터가 늘어 부족하면 페이지 나눔을 추가한다.
- 로컬에서 DB 통합 테스트를 돌리려면 사용자가 `health_test`를 만들고 마이그레이션을 적용해야 한다. 지금 DB 계정은 DB 생성 권한이 없다.
- 다크 모드와 실제 휴대폰은 확인하지 않았다.
