# #29 음식 영양성분 저장소와 출처 규칙

- 이슈: [#29](https://github.com/sirloinbh/health-log/issues/29)
- 브랜치: `feat/29-food-db`

## 목적

프랜차이즈 메뉴, 레토르트 식품, 즐겨먹는 음식의 조사 결과를 출처와 함께 저장할 곳을 만든다. 출처와 확인 날짜가 없으면 수치가 정확한지 나중에 검증할 수 없다.

## 변경 — 2026-10-31

- **DB:** `database/migrations/002_foods.sql`. 영양성분은 1회 제공량 기준이고 모르는 값은 NULL이다. 음수와 0 이하 제공량은 DB도 거부한다. 이름과 브랜드 조합은 중복될 수 없다.
- **API:** `backend/src/foods.ts`. `GET /api/foods?q=`, `POST /api/foods`, `PUT /api/foods/:id`. 삭제는 이슈 범위 밖이다.
- **검증 규칙:** 공식·공공 자료는 출처 주소와 확인 날짜, 제품 표기는 확인 날짜가 필수다. 출처 주소는 http와 https만 받는다.
- **조사 데이터:** 새 도구 없이 마이그레이션의 `ON CONFLICT`로 넣는다. 재실행해도 중복되지 않고, 확인 날짜가 더 새로운 조사만 날짜 있는 기존 값을 바꾼다.
- **화면:** `frontend/src/foods.tsx`. 음식 메뉴, 검색, 추가·수정. 0과 "값 없음"을 구분해 표시한다.
- **규칙 문서:** `docs/food-data.md`.
- **오류 처리:** `backend/src/app.ts`의 자체 오류 처리를 공통 `standard/http.ts`의 `notFound`, `errorHandler`로 바꿨다. 404 응답에 `HttpError`가 필요했다.
- **테스트 안전장치:** 이 PC의 `TEST_DATABASE_URL`이 다른 프로젝트의 `study_test`를 가리키는 것을 발견했다. 쓰기가 있는 통합 테스트는 DB 이름이 `health_test`일 때만 실행하고, 아니면 이유를 표시하며 건너뛴다.

## 1차 리뷰 보완 — 2026-10-31

독립 리뷰 지적 13건 중 10건을 고쳤고, 2건은 [#52](https://github.com/sirloinbh/health-log/issues/52)로 분리했으며, 1건(CodeQL)은 아래에 따로 적었다.

- **조사 데이터 규칙:** 확인 날짜가 지워진 음식을 재실행이 덮어쓰던 분기를 없앴다. 같은 날짜의 정정은 무시되므로 `UPDATE`로 하도록 문서에 적었다.
- **숫자:** 소수 셋째 자리 이하는 반올림되거나(`0.004`→0) DB 제약 위반으로 500이 났다. 이제 한국어 오류로 거부한다.
- **날짜:** 미래 날짜는 이후 조사를 영구히 막을 수 있어 거부한다. `0000-01-01`도 거부한다.
- **화면:** 숫자 칸의 잘못된 입력이 "값 없음"으로 저장되던 문제, 저장 중 취소로 다른 창이 닫히던 문제, 검색에 가려진 음식의 저장 성공이 보이지 않던 문제, 검색하지 않은 글자가 저장 후 적용되던 문제를 고쳤다.
- **검증 틈:** `http:foo` 거부, 객체가 아닌 본문의 한국어 오류, 출처 규칙의 DB 제약을 추가했다.
- **테스트:** `%` 검사가 이스케이프를 실제로 검증하게 고쳤다. 통합 테스트가 `docs/food-data.md`의 SQL을 그대로 읽어 실행한다.
- **브라우저 재확인:** 숫자 칸에 실제 키로 `1e`를 치면 오류로 안내되고 고치면 저장된다. 전체 흐름도 양쪽 크기에서 다시 통과했다.

- **CI 결과(`6e9edc0`):** `ci / verify`에서 `health_test`로 백엔드 31개 통과, 건너뜀 0개, 프론트엔드 93개 통과.

## 2차 리뷰 보완 — 2026-10-31

지적 6건 중 5건을 고쳤고, 1건은 [#53](https://github.com/sirloinbh/health-log/issues/53)으로 분리했다. 리뷰는 2회까지이므로 3차 리뷰는 하지 않는다.

- **규칙 문서:** "재실행해도 고친 값이 유지된다"는 항상 참이 아니었다. 경우별 결과를 표로 적고, `UPDATE` 정정도 재실행에 안전한 형식을 적었다.
- **숫자:** 허용 오차 때문에 `5e-9` 같은 값이 통과해 500이나 0 저장으로 이어졌다. `toFixed(2)` 비교로 바꿔 소수 둘째 자리 값만 받는다.
- **검색:** 실패한 검색어가 저장 후 재조회에 쓰여 목록이 비던 문제를 고쳤다.
- **테스트:** 오늘 날짜 허용, `public`·`label`의 DB 제약 검사를 추가했다.

### CodeQL 경고

CodeQL이 `js/missing-rate-limiting`(요청 횟수 제한 없음) 3건을 `backend/src/foods.ts`의 새 라우트에 보고했다. 필수 검사는 아니지만 실패 상태였다.

- 중앙 결정(`project-standards#291`)은 `frontend/nginx.conf`의 `limit_req`(IP당 초당 10개, burst 40, 429)로 제한하고 경고를 해제하는 것이다.
- 사용자가 해제 대신 경고 내용을 반영하기로 해서 `backend/src/rate-limit.ts`를 추가했다. 패키지 설치 없는 메모리 기반 미들웨어이고, 주소당 1분에 700회까지 받는다. nginx가 1분에 통과시키는 최대 640회보다 커서 평소에는 동작하지 않고, API에 직접 접근하는 경우를 막는다.
- `/api/health`는 제한에서 뺐다. 제한 중에도 상태 확인이 응답해야 한다.
- 제한: 기록이 메모리에만 있어 서버를 재시작하면 초기화된다. 프록시 뒤에서는 모든 요청이 nginx 주소로 보이지만, 사용자가 한 명이라 문제가 없다.

## 제한·후속

- 음식 삭제는 없다. 필요하면 식사 기록(#30)과의 관계를 정한 뒤 별도 이슈로 다룬다.
- 검색 결과는 100개까지 표시한다. 조사 데이터가 늘어 부족하면 페이지 나눔을 추가한다.
- 로컬에서 DB 통합 테스트를 돌리려면 사용자가 `health_test`를 만들고 마이그레이션을 적용해야 한다. 지금 DB 계정은 DB 생성 권한이 없다.
- 다크 모드와 실제 휴대폰은 확인하지 않았다.
