### 고른 기준

공식 이름이 정확히 일치하는 전국 대표 평균 자료만 썼다. 같은 이름의 자료가 여러 개면 아래 순서로 골랐고, 임의로 고르지 않았다.

1. 외식 → 가정식 → 산업체·학교 급식
2. 실제 분석값 → 계산으로 낸 산출값
3. 최신 생성일
4. 그래도 여러 개면 열량 중앙값 (피자, 핫도그, 아메리카노)

### 환산

자료는 100g(또는 100mL)당 값이다. 1인분으로 쓰기 쉽게 자료의 총 내용량으로 환산해 소수 둘째 자리까지 저장했다. 예를 들어 김치찌개는 100g당 61kcal, 총 내용량 400g이므로 `400g`, `244kcal`이다. 총 내용량이 없거나 100g인 자료는 100g 기준 그대로다.

## 제한·후속

- **숫자는 자료에 적힌 그대로다.** 틀려 보여도 고치지 않았다. 예를 들어 라면은 590mL에 나트륨 342mg, 스파게티는 395mL에 205mg으로 일반적인 인식보다 낮다. 산출값이 많은 외식 면·국 종류는 참고값으로 본다.
- **자료의 0도 그대로 저장했다.** 김밥과 된장찌개의 당류 0처럼 실제 0이 아니라 미측정일 수 있는 값이 있다. 자료만으로는 구분할 수 없다.
- **총 내용량이 1인분이 아닐 수 있다.** 피자는 558g 1,440kcal로 한 판에 가깝다. 쌀밥은 100g(166kcal)이라 한 공기는 2회 정도로 입력해야 한다. 화면에 제공량이 표시되므로 수량으로 조절한다.
- **단위가 mL인 자료가 있다.** 산출값 자료는 자료 자체가 mL를 쓴다(현미밥 300mL 등).
- **못 찾은 이름:** 김치볶음밥, 제육덮밥, 참치김밥, 양념치킨, 보쌈은 일치하는 대표 자료가 없어 넣지 않았다. 추정값으로 넣지 않았다.
- **대표 자료가 다른 메뉴:** 불고기는 소불고기, 돈까스는 돈가스, 닭갈비는 닭볶음(닭갈비), 찜닭은 닭찜으로 찾아야 한다.
- 음식 목록 화면은 한 번에 100개까지 보여 준다. #31, #32로 음식이 늘면 페이지 나눔이 필요하다.
- 값을 다시 받으려면 공공데이터포털 Open API 키를 쓰는 편이 안정적이다. 이번에는 키 없이 공개 페이지를 요청 간격을 두고 읽었으며, 그 스크립트는 저장소에 넣지 않았다.
