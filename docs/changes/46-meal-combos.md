# #46 자주 먹는 조합 저장하고 한 번에 기록하기

- 이슈: [#46](https://github.com/sirloinbh/health-log/issues/46)
- 브랜치: `feat/46-meal-combos`

## 목적

함께 먹는 음식을 매번 하나씩 고르지 않도록, 조합으로 저장해 두고 한 번에 기록한다.

## 범위 조정

처음 이슈에는 할 일이 세 가지 있었다. 조합, 다른 날의 끼니 복사, 최근 먹은 음식 먼저 보여주기다. 목적이 서로 달라 한 PR로 리뷰하기 어려우므로 나눴다.

- 다른 날의 끼니 복사: [#75](https://github.com/sirloinbh/health-log/issues/75)
- 최근 먹은 음식 먼저 보여주기: [#76](https://github.com/sirloinbh/health-log/issues/76)

## 정한 규칙

요구사항에 없던 규칙이다. 사용자 확인 없이 [#46 댓글](https://github.com/sirloinbh/health-log/issues/46#issuecomment-6620682075)에 기록하고 진행했다. 다르게 원하면 후속 이슈로 고친다.

- **항목:** 음식 저장소의 음식만 넣는다. 직접 입력한 음식은 넣지 않는다.
- **크기:** 조합 하나에 1~20개다. 같은 음식은 한 번만 넣는다.
- **수량:** 식사 기록과 같다. 0보다 크고 999 이하, 소수 둘째 자리까지다.
- **이름:** 1~50자이고 다른 조합과 겹칠 수 없다. 대소문자는 구분하지 않는다.
- **기록:**
  - 고른 끼니 하나에 조합의 음식을 모두 기록한다.
  - 각 음식은 기록하는 순간의 영양성분을 복사한다. 조합을 고쳐도 이미 기록한 식사는 그대로다.
  - 하나라도 실패하면 아무것도 기록하지 않는다.
- **음식이 사라지면:** 앱에는 음식 삭제 기능이 없다. DB에서 음식을 지우면 그 음식은 조합에서도 빠진다(`ON DELETE CASCADE`). 음식이 모두 빠진 조합은 기록할 수 없고, 수정하라고 안내한다.

## 변경 — 2026-11-04

- **DB** `database/migrations/007_meal_combos.sql`:
  - `meal_combos`와 `meal_combo_items` 테이블을 만든다.
  - 이름은 `lower(name)` 고유 인덱스로 겹치지 않게 한다.
  - 항목 순서(`position` 1~20), 같은 음식 중복 금지, 수량 범위를 DB도 강제한다.
- **API** `backend/src/combos.ts`:
  - `GET /api/combos`: 조합마다 음식과 칼로리 합계를 돌려준다. 합계는 DB의 `NUMERIC`으로 계산해, 기록했을 때 더해질 값과 같다.
  - `POST /api/combos`, `PUT /api/combos/:id`: 이름과 음식 목록을 한 트랜잭션으로 저장한다. 없는 음식이 섞이면 아무것도 저장하지 않는다(400).
  - 같은 이름은 409로 거절한다.
  - `DELETE /api/combos/:id`: 204로 답한다.
- **기록 API** `backend/src/meals.ts`:
  - `POST /api/meals/:date/combos/:id` (`{ meal }`)를 추가했다. 조합의 음식을 `INSERT … SELECT` 한 문장으로 넣으므로 전부 들어가거나 하나도 안 들어간다.
  - 없는 조합은 404, 음식이 없는 조합은 400이다.
  - 수량 규칙(`servingsInput`)은 식사 기록과 조합이 같이 쓴다.
- **화면**
  - `frontend/src/combos.tsx`: 메뉴에 "조합" 화면을 더했다. 목록, 추가·수정 대화상자(음식 검색, 넣기·빼기, 수량), 삭제 확인이 있다. 수량은 #70과 같은 방식으로 읽어 쉼표 입력을 막는다.
  - `frontend/src/meals.tsx`: 식단 카드에 "조합에서 고르기"를 더했다. 고른 끼니에 기록하고, 오류는 조합 버튼 옆에 보인다.
    - 조합 목록은 버튼을 누를 때만 불러온다. 하루를 열 때 요청이 늘지 않는다.
  - `frontend/src/combo-text.ts`: 조합 타입과 요약 문구("음식 2개 · 520kcal")를 두 화면이 같이 쓴다.
  - `frontend/src/number-input.ts`: 소수 둘째 자리 검사를 두 화면이 같이 쓰도록 옮겼다.

## 1차 리뷰 반영 — 2026-11-04

- **삭제 뒤 포커스:** 조합을 지우면 카드와 버튼이 사라져 키보드 포커스가 `<body>`로 갔다. 이제 페이지 제목 "조합"으로 옮긴다. 하루 기록의 식단 카드와 같은 방식이다. 고치기 전 코드에서 이 테스트가 실패하는 것을 확인했다.
- **수량 999 초과:** 서버는 "수량이 너무 큽니다"라고만 답해 어느 음식인지 알 수 없었다. 이제 보내기 전에 "<음식> 수량은 999 이하로 입력해 주세요"라고 안내한다.
- **분리:** 추가·수정 대화상자를 닫으면 포커스가 `<body>`로 가는 문제는 음식 화면과 같은 구조다. 두 화면을 함께 고치도록 [#78](https://github.com/sirloinbh/health-log/issues/78)로 나눴다.

## 2차 리뷰 반영 — 2026-11-04

- **느린 다시 읽기에서 포커스:** 1차 수정은 목록을 다시 읽는 응답이 빠를 때만 맞았다.
  - 원인: 다시 읽기가 대화상자 닫힘 애니메이션(200ms)보다 늦으면, 대화상자가 지운 카드의 "삭제" 버튼으로 포커스를 돌려준다. 그 뒤 목록이 갱신되면 버튼이 사라져 포커스가 다시 `<body>`로 갔다.
  - 수정: 삭제가 끝나면 다시 읽기를 기다리지 않고 그 카드를 바로 화면에서 뺀다.
  - 테스트: 다시 읽기를 붙잡아 둔 상태에서 카드가 먼저 사라지는지 확인한다. 고치기 전 코드에서 이 테스트가 실패하는 것을 확인했다.
  - 한계: jsdom에는 닫힘 애니메이션이 없어, 포커스가 버튼으로 돌아갔다가 사라지는 과정 자체는 재현하지 못한다.

## 제한·후속

- 식사 기록에서 바로 "이 끼니를 조합으로 저장"하는 기능은 없다. 조합 화면에서 만든다.
- 조합을 기록할 때 수량 배수(예: 조합 2인분)는 없다. 저장한 수량대로 기록한다.
- 다크 모드와 실제 휴대폰, Firefox, Safari는 확인하지 않았다.
- 실제 DB와 연결한 화면은 확인하지 못했다.
